- realtime-tex needs native TeX plus a library host or its VS Code extension. TeXpresso uses a native viewer and external editor on Linux / macOS. Texifier is a commercial macOS / iOS app with external / cloud typesetter fallback; the fallback engine list is not established here. TeXlyre collaboration also needs signaling. Overleaf uses server compilation and is available as a hosted service or server installation.
- Package support depends on the engine and available resources. Rex ships selected packages; the other tools use installed TeX packages, integrated typesetters or TeX Live resources as indicated above.
- Rex applies verified glyph, rule and image patches and runs a full compilation after idle. realtime-tex updates paragraphs and environments with a background full pass. TeXpresso uses checkpoint / rollback and viewport rendering; Texifier typesets the visible region incrementally. texlode uses a resident server-side LuaTeX process and sends display lists to browser Canvas, with background layout convergence. TeXlyre uses full compilation with optional compile on save; TeXbrain uses full pdfTeX compilation with optional automatic compilation; Overleaf uses automatic server compilation.
- Rex and realtime-tex use references from the last full layout during live edits. Both settle provisional paragraph layout, float movement and footnote bodies / placement after a full pass. New or merged Rex paragraphs borrow the first captured context; growing lines remain anchored to the last full layout. Neighbouring text and page breaks settle after the full pass. TeXpresso propagates incremental layout changes, but its auxiliary-file workflow is not verified here. A live paragraph update does not imply that the entire document has repaginated.
- TeXpresso documents a viewer-focused workflow; PDF export and bibliography / index orchestration are not verified here. Texifier's live indexer is MakeIndex-compatible. Rex's document-level tools run through full compilation.
- Rex supports live edits in uniquely captured main-file and child-file paragraphs. Splits, merges and line-count changes can update provisionally; ambiguous repeated inputs use full compilation. Imported asset-byte changes, unsupported image clipping / PDF options and vector drawings use full compilation. All project files persist locally and export together. realtime-tex tracks `input`, `include` and `subfile` dependencies. TeXpresso relies on its external editor for project editing and any shared editing. Texifier Connect is being retired; see the notice below for its availability.
- Installation rows describe end-user requirements after deployment, rather than developer setup. realtime-tex's extension can install native TeX automatically; TeXpresso needs installed TeX Live or Tectonic resources. Texifier's local typesetter avoids project uploads, while its cloud fallback does not. TeXlyre can compile and edit alone without an application backend; collaboration needs signaling, and uncached packages need a download source. Overleaf compiles on a server even when self-hosted. License labels describe project-owned code, not all bundled engines, fonts or dependencies; those retain their own licenses.
- Mobile support checked on **2026-10-12**. Rex has [responsive layout checks](../tests/browser/ui.mjs) at desktop, tablet and phone widths and [mobile WebKit coverage](../tests/browser/webkit.mjs); these are automated browser checks, not physical-device tests. [TeXlyre](https://github.com/TeXlyre/texlyre#browser-compatibility) documents a mobile theme and Android PWA support, with mobile file-system and iOS sharing limitations. [Overleaf](https://www.overleaf.com/learn/how-to/Can_I_use_Overleaf_on_an_iPad_or_other_mobile_devices%3F) supports mobile browser access with touch, keyboard and PDF-viewer limitations. [Texifier](https://www.texifier.com/ios) provides an iPhone / iPad app. texlode's phone / tablet editing is not verified; browser access alone is not taken as evidence of a mobile editing workflow.

- TeXbrain's [official feature and limitation documentation](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/README.md#features) covers local compilation, cached offline resources, Git integration, on-demand packages and its pdfTeX-only engine. Bibliographies use a simplified fallback or a supplied `.bbl`, without BibTeX / Biber. Direct folder access requires Chromium; other supported browsers use browser storage.
- TeXbrain's [compiler](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/src/lib/compiler/latex-engine.ts#L166) compiles the selected main file, rerunning when required; caching unchanged input files is not partial-document typesetting. Its [automatic compilation](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/src/routes/editor/+page.svelte#L455) waits one second after edits. [Source-to-PDF navigation](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/src/routes/editor/+page.svelte#L499) uses [text matching / approximate scrolling](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/src/lib/ui/PdfViewer.svelte#L237); reverse navigation is not verified. Responsive layout code alone is not taken as evidence of a verified phone / tablet editing workflow.
- TeXbrain includes a [Yjs / WebRTC collaboration provider](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/src/lib/collab/provider.ts#L81) and a [room panel](https://github.com/swimmingbrain/texbrain/blob/57b6a32b4d33cf94deb0b1c9260bb991df86cb86/src/lib/ui/CollabPanel.svelte), but the reviewed editor page imports the panel without rendering it. Shared editing is therefore marked unverified; the provider uses external signaling. Its built-in Git integration also requires a CORS proxy for remote operations, separate from local compilation.

## Performance comparison

### Performance coverage and gaps

The README distinguishes **warm preview latency** (an edit through preview drawing) from **native paragraph latency** (a compiler request through decoded display-list output). Warm means the engine and resources are already loaded. The native timer includes encoding, IPC, compilation, traversal, serialization and decoding; it excludes the editor, WASM, network and drawing. Neither measures the time from a physical keystroke until pixels appear on screen. The published texlode samples are a third workload, with different machines and statistics, so their timings remain separate.

Coverage reviewed on **2026-10-12**. This comparison includes published texlode evidence, TeXbrain documentation / source review and a [measured realtime-tex VS Code preview pipeline](performance.md#realtime-tex-vs-code-preview-measurements). A missing timing means that the report has no matching measurement, not that the tool lacks preview support or is slower.
